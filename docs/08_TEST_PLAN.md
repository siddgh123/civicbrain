# 08 — Test Plan

**7-day MVP (until 7 Oct 2026):** the mandatory tests are the list in `09_BUILD_PLAN_7DAY.md` §4; the suites below are the full (Phase 2) plan.

Rule: **a task is done only when its tests exist and the relevant verify command is green**. The agent pastes the command and its summary line into `docs/PROGRESS.md`. Tests are never deleted, skipped or weakened to get green; a flaky test is fixed or quarantined with an issue and a date.

`scripts/dev/verify-all.ps1` runs DB → backend → AI → frontend → E2E in order and stops at the first failure; its exit code (and the log in `logs/verify-all_<timestamp>.txt`) is the only proof that a phase is green. Components not built yet show SKIP; `-SkipE2E` when the E2E stack is not running; `-SkipDb` before P1; `-RebuildTestDb` to rebuild `civicbrain_test` first. The backend and AI steps run without the `.env` values (like CI).

## 3. Mandatory test suites (by requirement)
- **Auth (FR-01..03):** register → OTP → login; register with an existing e-mail **or** phone → 202 with a decoy otpId, no second account, owner gets a mail; forgot-password for an unknown e-mail → 202 with an otpId of the same shape; OTP code never appears in `notifications`/`notification_outbox`; wrong OTP 5× → locked code; expired OTP; 10 wrong passwords then the correct one → 423, a wrong one while locked → 401; unknown account 11× → 401 each time; generic error for unknown account (same status + message); refresh rotation; reuse of rotated refresh → family revoked + 401; logout clears cookie; logout-all invalidates existing access token (`iat < token_valid_after`); officer login requires TOTP; TOTP replay same step rejected; RFC 6238 vectors; password blocklist; password change revokes sessions; CSRF header missing on refresh → 403.
- **Authorization matrix (API1/API5):** a parameterised test with one row per endpoint × role (CITIZEN, CITIZEN_OTHER, OFFICER_IN_SCOPE, OFFICER_OUT_OF_SCOPE, ADMIN, CONTRACTOR_ASSIGNED, CONTRACTOR_OTHER, STAFF, ANONYMOUS) and the expected status (200/201/204/401/403/404). A reflection test lists all `@RequestMapping`s and fails if any endpoint has no row.
- **Accounts (FR-04, FR-05):** admin creates an officer with scopes, disables it (login refused, tokens revoked); officer creates a contractor → one-time password returned once, `must_change_password` forces the change screen/403 on other endpoints until changed; `bootstrap-admin` runner refuses when an ADMIN exists.
- **Complaint intake (FR-10..12, FR-14):** happy path (201, `publicRef`, ward 1–23, history row, outbox row, job row, `depth_answer`/`a4_in_frame` stored); depthAnswer missing for Pothole or present for Garbage → 400 `VALIDATION_FAILED` (field error); each validation failure returns its code (`CAPTURE_SESSION_INVALID`, `CAPTURE_SESSION_EXPIRED`, `GPS_ACCURACY_TOO_LOW`, `LOCATION_STALE`, `OUTSIDE_BOUNDARY`, `FILE_TYPE_NOT_ALLOWED`, `FILE_TOO_LARGE`, `IMAGE_TOO_SMALL`, `IMAGE_TOO_LARGE_PIXELS`, `RATE_LIMITED`); support vote twice → still one vote; capture session cannot be reused; stored file has no EXIF; download of another user's photo → 404.
- **Lifecycle (V2 rules):** every allowed transition by the right role succeeds and creates history + outbox; every disallowed transition → 409 `INVALID_TRANSITION`; wrong role → 403 `ROLE_NOT_ALLOWED`; merged child owners receive master notifications; officer accept (SUBMITTED → VERIFIED) and restore (REJECTED → VERIFIED) work and appear in the timeline; **COMPLETED → REOPENED → generate → approve succeeds** and remove-from-plan frees the complaint (V5 trigger).
- **AI pipeline:** golden image tests (YOLO box IoU ≥ 0.5 with the recorded box; class matches); measurement Tier A on `a4_pothole.jpg` within ±15 % of the tape value recorded in the fixture; Tier B maths unit tests with synthetic camera geometry (known answers); Tier C fallback when no pitch; estimate formulas (worked example: 0.6 × 0.4 m medium pothole → cut 0.63 m², ≈ 78 kg mix, ≈ 0.16 kg tack); duplicate scoring reproduces 3 pairs from `data/duplicates/duplicate_engine_results.csv` within 0.001; **priority golden test 0 mismatches** on `data/priority/priority_factor_dataset.csv` vs `data/priority/priority_scores.csv`; authenticity scoring table cases; idempotency (run analyze twice → same rows); job retry/DEAD path (DEAD → `ai_status = FAILED`); stale RUNNING job requeued by `fn_requeue_stale_jobs` (NFR-03); text-vs-category mismatch → `is_accepted = false` badge data (FR-21); measurement tier letter stored in `assumptions.tier` and returned by the API (NFR-07); best photo: a sharp fixture outranks its blurred copy (`quality_score`); a DUPLICATE whose master is CLOSED is stored as UNCERTAIN; ANALYZE_IMAGE flags a completion photo equal to the citizen photo (FAIL row with `image_id`).
- **Optimizer:** fixture of 12 jobs + a fixed OSRM matrix → deterministic plan (same order twice), no stop after 17:00, every job either planned or dropped with a reason, 10-s limit respected; RETIME keeps order; OSRM down → run FAILED with the documented message.
- **Plans API:** (backend IT inserts the DRAFT plan as the worker would; the real generate path is E2E-03) edit with stale version → 409; edit a non-DRAFT plan → 409 `PLAN_STATE_CONFLICT`; cancel an ASSIGNED plan → its complaints back to VERIFIED and plannable; cancel with work started → 409; plan becomes IN_PROGRESS at the first inspection and COMPLETED when all items are done; every P0001 message prefix maps to its code; approve moves complaints to SCHEDULED; assign to wrong-work-type contractor → 422 `CONTRACTOR_NOT_ELIGIBLE`; PDF and XLSX download (content-type, non-empty, plan code inside); only officers.
- **Field work:** inspection with contractor 240 m away → saved with warning flag; completion proof identical to citizen photo → reuse flag visible to officer; verify approve → CLOSED; verify reject → REOPENED.
- **Notifications (FR-38, FR-50..52):** one status change → exactly one e-mail per recipient in the Mailpit container (its API `/api/v1/messages`) and one WhatsApp request to the fake provider (WireMock); no WhatsApp without `whatsapp_opt_in` (FR-52); a status without a template (VERIFIED) creates no rows; ACTION_PLAN_ASSIGNED goes to the contractor user and COMPLETION_SUBMITTED to the assigning officer; officer notification log lists them (FR-38); dispatcher run twice → no duplicates (dedupe_key); provider 500 → retry schedule; webhook with bad signature → 401; COMPLETED e-mail has the proof photo inline + attached.
- **Privacy (FR-37, FR-60..62):** consent withdrawal reflected in `v_current_consents`; export contains only own data; erasure anonymises (`deleted-<id>@invalid.invalid`, no phone, login impossible); blur job writes `blurred_storage_key`; approval before the blur → 409 `BLUR_NOT_READY`, without consent → 422 `CONSENT_MISSING`; public map has no personal fields and snapped coordinates; unapproved photo not reachable via public endpoint.
- **Headers:** a test asserts CSP, HSTS (when HTTPS), nosniff, frame-ancestors, Permissions-Policy on `/` and `/api/v1/public/categories`.

## 4. E2E scenarios (Playwright)
Config: `workers: 1`, `fullyParallel: false` (one shared database); accounts from `.env.test` via `process.loadEnvFile('../.env.test')`; `projects: [{name:'desktop', use: devices['Desktop Chrome']}, {name:'mobile', use: {...devices['Pixel 7'], permissions:['geolocation','camera'], geolocation:{latitude:18.7440, longitude:73.6760, accuracy:8}, launchOptions:{args:['--use-fake-ui-for-media-stream','--use-fake-device-for-media-stream','--use-file-for-fake-video-capture=' + path.resolve(import.meta.dirname, '../tests/fixtures/images/camera.y4m')]}}}]` (absolute path — Chrome resolves relative paths against its own working directory; `import.meta.dirname` because `package.json` has `"type": "module"`, so `__dirname` does not exist), `webServer` entries only for the frontend (backend, worker, DB started by `scripts/dev/start-e2e.ps1`). Camera faking works only in Chromium; iPhone behaviour is tested manually on a real device (checklist in `13_DEMO_AND_DEPLOY.md`). Citizen and contractor specs run only in `mobile` (plus a `mobile-360` project: same settings with `viewport: {width: 360, height: 740}` for NFR-04); officer, admin, download and axe-desktop specs only in `desktop` (use `testMatch`/`grep` per project). Every run starts from a reset database: `verify-all.ps1` runs `seed-e2e.ps1 -NoPackage` before Playwright, and E2E-01 registers `citizen+<runId>@test.local` so repeated runs never collide. "Green three runs in a row" (P9) = three consecutive `verify-all.ps1` runs.
1. **E2E-01 Citizen journey:** register → OTP from Mailpit → login → report pothole via fake camera → sees CB number → worker verifies within 60 s → status "Under review".
2. **E2E-02 Duplicate:** citizen2 reports 40 m away with similar text → MERGED → citizen2 sees "Linked to CB-…".
3. **E2E-03 Officer plan:** officer (TOTP) filters New → generate plan → edit order → approve → assign contractor → both citizens have "Contractor assigned" e-mails.
4. **E2E-04 Contractor:** contractor login → worklist → inspection (fake camera, tape values) → start → completion proof.
5. **E2E-05 Close & reopen:** officer verifies → CLOSED → citizen rates 4 stars; second complaint: citizen "Not fixed" → REOPENED.
6. **E2E-06 Security:** citizen tries officer URL → redirected/403 page; contractor opens another firm's complaint URL → 404 page; logout in one tab logs out the other.
7. **E2E-07 Downloads:** officer downloads PDF and XLSX of a plan.
8. **E2E-08 Accessibility:** axe scan on landing, register, new complaint, officer complaints, contractor today and contractor inspection form → 0 serious/critical (P4 citizen pages, P7 officer pages, P9 contractor pages).

## 6. CI (GitHub Actions, public repo = free standard runners) — `.github/workflows/ci.yml` (in the kit)
On push to `main`/`phase/**` and on PRs. Every third-party action is pinned to a full commit SHA. A job whose folder does not exist yet prints a notice and passes; once the folder exists it is mandatory.
- `db`: service `postgis/postgis:18-3.6`; `scripts/ci/check-migrations.sh` (db/ vs flyway/ vs backend copies); `scripts/ci/db-tests.sh` twice (build from `flyway/` and from `db/`: roles → V1–V5 → R__ → seed → R__ again → all `db/tests`); E2E reset check (reference data kept, tests still green, guard refuses other DBs).
- `backend`: Temurin 25, `./mvnw -B verify` (Testcontainers ITs, JaCoCo line coverage ≥ 70 % enforced in the pom); reports uploaded on failure.
- `frontend`: Node 24, `npm ci`, lint, typecheck, `npm run test:coverage`. Fails if `frontend/src` exists without a committed `package-lock.json`.
- `ai`: Python 3.13, CPU PyTorch first, `requirements-dev.txt`, `ruff check`, `pytest`; a PostGIS service with a test DB built by `db-tests.sh` for the integration tests. Tests that need model files (YOLO weights, MiniLM, YuNet) are marked `@pytest.mark.models` and **skip only when the files are absent** (CI); at the P2/P6/P11 gates they run locally with the real files and a skip there counts as a failure; `HF_HUB_OFFLINE=1`.
- `security`: gitleaks-action v3 (whole history; `GITLEAKS_LICENSE` secret only for organization-owned repos), Trivy fs scan with trivy-action v0.35.0 + Trivy v0.69.3 (the known-safe versions after the March 2026 supply-chain attack, GHSA-69fq-xp46-6x23), `npm audit --omit=dev --audit-level=high`, `pip-audit` on the Windows lock file.
- Nightly (added in P10 as `nightly.yml`): E2E on Ubuntu with all services, ZAP baseline against the started app, OWASP Dependency-Check (needs an NVD API key). Private repo instead: 2,000 free minutes/month — run E2E and ZAP nightly only.

## 7. Performance smoke (k6)
20 virtual users for 2 minutes: officer list (p95 < 500 ms), complaint detail (p95 < 500 ms), public map (p95 < 300 ms); 5 users submitting complaints with a 300 KB image (p95 < 2 s). Fail the run if error rate > 1 %.
