# Backend rules (Spring Boot 4.1.1, Java 25)

- Package `com.civicbrain.<module>.{api,service,repo,model}` as in `docs/02_ARCHITECTURE.md` §3. Controllers use DTOs (Java records) only; never return entities; one request and one response DTO per role where fields differ.
- `spring.jpa.hibernate.ddl-auto=validate`, `open-in-view=false`, Flyway owns the schema (`baseline-on-migrate: true`, `baseline-version: 1`, `placeholder-replacement: false`, dependency `org.flywaydb:flyway-database-postgresql`). Migrations = the kit's `flyway/*.sql` copied unchanged (V1–V5 + repeatable `R__civicbrain_grants.sql`). Flyway connects as the owner (`spring.flyway.user/password` = `${PG_ADMIN_USER}/${PG_ADMIN_PASSWORD}`) in the `dev`, `demo`, `e2e`, `e2e-seed` and `bootstrap-admin` profiles (every profile that runs against a real database); the datasource is always `civicbrain_app` (`DB_USER`). Tests do not set a Flyway user (Testcontainers `@ServiceConnection`). Hibernate Spatial with the normal PostgreSQL dialect (no `PostgisPG*Dialect`); geometry type `org.locationtech.jts.geom.Point` SRID 4326.
- Map only the tables the module needs; column names exactly as `db/SCHEMA_REFERENCE_after_V5.sql`. Generated columns (`complaints.public_ref`) are `insertable=false, updatable=false`. Enums stored as strings matching the DB CHECK lists.
- Complaint status is changed ONLY through `WorkflowActor.changeStatus(...)` which sets `civicbrain.actor_user_id`, `civicbrain.actor_role`, `civicbrain.status_remarks` with `set_config(..., true)` in the same transaction. Plans: call `fn_approve_action_plan` / `fn_assign_action_plan` via `JdbcClient`.
- Validation with Jakarta Bean Validation on every DTO; `spring.jackson.deserialization.fail-on-unknown-properties=true`.
- Errors: throw typed exceptions (`ApiException(code, status, detail)`); one `@RestControllerAdvice` returns RFC 9457 bodies per `docs/12_ERROR_HANDLING.md` (SQLSTATE mapping §3).
- Security per `docs/07_SECURITY.md`: deny-all default, method security, ownership in queries (404), Argon2id encoder, JWT with `typ`, `aud`, `iss`, `token_valid_after` check, refresh cookie `__Host-cb_rt`, CSRF header on refresh/logout.
- Config through `@ConfigurationProperties` records with `@Validated`; required env vars fail startup with a clear message. No secrets in `application.yml`. Keys that may be empty in `.env` (SMTP user/password, Meta/Twilio, `LABOUR_RATE_PER_HOUR`, `APP_EXTRA_ORIGINS`) get defaults, e.g. `${SMTP_USER:}` — Windows cannot hold empty environment variables.
- Password hashing: `Argon2PasswordEncoder` needs BouncyCastle — add `org.bouncycastle:bcprov-jdk18on` with an explicit version (Spring Boot does not manage it; use the newest 1.8x release on Maven Central, 1.83 or later).
- Logging: SLF4J with MDC `requestId`, `userId`; mask phones; never log bodies, tokens, OTPs.
- Time: inject `java.time.Clock`; store `OffsetDateTime`/`Instant` in UTC.
- Tests: unit classes end in `Test` (surefire), integration classes end in `IT` (failsafe, run by `verify`); JUnit + AssertJ; integration tests with Testcontainers `postgis/postgis:18-3.6` (`DockerImageName.parse(...).asCompatibleSubstituteFor("postgres")`, `@ServiceConnection`, shared container); Testcontainers 2.0.x; `spring-security-test` JWT helpers; JaCoCo ≥ 70 % lines.
- Profiles: `dev` (default), `demo`, `test` (all tests: `src/test/resources/application-test.yml` with obviously fake, non-secret values for every required property — secrets = base64 of `test-only-…`, `STORAGE_ROOT=${java.io.tmpdir}/cb-test`, `WHATSAPP_PROVIDER=log`; tests never need `.env`), `bootstrap-admin` (non-web, schedulers off; `AdminBootstrapRunner` reads `BOOTSTRAP_ADMIN_EMAIL/NAME/PASSWORD`, refuses if any ADMIN exists, creates the ADMIN through the user service with e-mail verified (TOTP set-up is forced at first login ONLY when `app.security.mfa-required=true`, i.e. after the optional P25; in the MVP (`false`) the admin logs in with e-mail + password, no TOTP step), then exits; started by `scripts/dev/bootstrap-admin.ps1`), `e2e` (Playwright stack on `civicbrain_e2e`; rate limits relaxed per `04_API_CONTRACT.md` §11), `e2e-seed` (non-web, schedulers off (`app.scheduling.enabled=false`); `E2eSeedRunner` creates the fixed accounts from the `E2E_*` environment variables (`seed-e2e.ps1` loads `.env.test`) through the real services and exits; it throws unless the JDBC database name ends with `_e2e`). Nothing test-only may be reachable in `dev`/`demo` (no test endpoints, no seeding).
- Origin check for `/auth/refresh` and `/auth/logout`: `APP_BASE_URL` plus the comma list `APP_EXTRA_ORIGINS` (dev only).
- Build: `.\mvnw.cmd -q verify` must pass before any commit.
